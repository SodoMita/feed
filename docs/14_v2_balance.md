# ⚖️ Баланс v2 — спецификация чисел, знаков и цветов

## 1. Принцип: карточка отвечает за свои числа

**Масштаб числовых метрик берётся от этапа самой карточки, а не от номера хода.**

Раньше дельта масштабировалась по `stageForCount(state.cardCount)` — одна и та же карточка
давала разные числа в зависимости от того, на каком ходу выпала. Согласовать текст с результатом
было невозможно. Теперь:

```ts
// gameEngine.ts
const deltaStage = card?.stage ?? stageForCount(state.cardCount);
const { metrics, scaledDelta } = applyDelta(state.metrics, choice.delta, deltaStage);
```

То же в предпросмотре при наклоне (`App.tsx`): `scaleDelta(rawHoverDelta, currentCard?.stage ?? state.stage)`.
Число, показанное при наклоне, всегда равно числу, которое придёт после выбора.

**Инвариант:** если текст карточки называет сумму или количество — она равна масштабированной дельте.
Если совпадение невозможно (например, «вирусные 50к просмотров» — это не метрика), точное число убрано.

## 2. Знак и цвет (спецификация)

### 2.1 Превью числовой метрики при наклоне (`NumberMetric`)

| Дельта | Знак | Цвет | Смысл |
|---|---|---|---|
| > 0 | `+` | зелёный (emerald) | лайк |
| < 0 | `−` | красный (red) | дизлайк |
| 0 | — | нейтральный | нет эффекта |

Знак и цвет вычисляются **от дельты**, а не от результирующего значения.
Было: `preview < 0 ? '−' : '+'` (знак зависел от итога) → при деньгах 10 000 и дельте −5 000
показывалось «+5 000». Стало: `delta < 0 → '−'` → корректно «−5 000».

### 2.2 Наклон карточки и кнопки (семантический цвет)

Цвет наклона, рамки подсказки и ховера кнопок определяется **смыслом выбора**, а не стороной:

| Выбор | Цвет | Значение |
|---|---|---|
| все дельты ≥ 0 | зелёный | как лайк — хорошо |
| все дельты ≤ 0 | красный | как дизлайк — плохо |
| смешанные (размен) | нейтральный | обмен, ни хорошо, ни плохо |

Функция: `choiceTone(delta)` → `'good' | 'bad' | 'mixed'`. Цвет стороны «лево/право»
остался как был (одна сторона — один цвет), но теперь он отражает суть варианта.

### 2.3 Иконки лайков/дизлайков

В экране результата единые ❤️ (лайки) и 💔 (дизлайки) — как в шапке метрик.

## 3. Проверка колоды

| Правило | Статус |
|---|---|
| У каждой карточки есть «безопасный» выбор (все дельты reach/soul/energy/money ≥ −1) | ✅ 81 из 102 карточек; остальные 21 — сознательно рискованные (обе стороны вредят) |
| Сумма безопасных дельт по колоде положительна для reach/soul/money | ✅ reach +12, soul +79, money +2 (в авторских единицах) |
| Энергия — дефицитный ресурс | ⚠️ сумма безопасных дельт energy = −5; карточки отдыха важны |

**Симуляция (2000 случайных раскладов, 40 карточек, жадная стратегия «спасай самую слабую
метрику»):** выживаемость ~25%, средняя смерть — карта 25. Основная причина смерти — 💰 деньги
(начинаются с 3 200 ₽ при размахе −5 000…−50 000 ₽ на этапе 2–3). Это не баг: деньги —
дефицитный ресурс, смерть от них — часть дизайна («Аккаунт продан»), а жадная стратегия
игнорирует деньги. Осознанная игра с балансировкой ранних этапов живёт дольше; карточки
«помощи» (отдых, рефлексия, возможность) компенсируют дефицит.

## 4. Что гарантировано после правок

1. Текст карточки и результат совпадают по числам (проверено по всем карточкам с числами).
2. Знак превью при наклоне корректен (зелёный «+» / красный «−»).
3. Цвет наклона семантический: красный = дизлайк/минус, зелёный = лайк/плюс.
4. `tsc --noEmit` и `vite build` проходят.
