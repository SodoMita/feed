# 15. Редизайн «Согласие / Отказ» (v3)

Дата: 2026-08-13. Источник: запрос игрока — «переделай карточки по принципу
согласия/несогласия; красный = несогласие, зелёный = согласие; почини layout
на больших экранах и прокрутку на телефоне».

## Принцип карточек

Каждая карточка теперь **предложение или вопрос** (стиль Reigns/Lapse).
Игрок не выбирает «левую/правую опцию» — он **отвечает персонажу**:

- свайп **вправо** → **зелёное ✓ «Да»** — согласится с предложением → `rightChoice`;
- свайп **влево** → **красное ✕ «Нет»** — отказаться → `leftChoice`.

Старые подписи выборов (`label`) в данных сохранены, но UI их больше не
рисует: подписи на карточке и кнопки постоянные («✕ Нет» / «Да ✓»).

### Как переформулированы тексты

Инвариант: **«Да» (правый свайп) всегда исполняет тот же сценарий, что раньше
исполнял `rightChoice`** — дельты, флаги, перки, концовки не тронуты.
Поэтому:

- для карт, где `rightChoice` — согласие («взять рекламу», «рискнуть»), текст
  стал прямым предложением: «Возьмёшь?»;
- для карт, где `rightChoice` — отказ/сопротивление (сделка Алины, финальный
  выкуп аккаунта, слияние с Виральным Королём и т.п.), вопрос инвертирован:
  «Откажешь?» — и «Да» подтверждает именно отказ;
- результаты выборов (`text` у выбора) не менялись, кроме одного:
  `resistance_meeting` (RU) — «Ты соглашаешься.» → «Ты становишься узлом.»,
  т.к. эта ветка теперь лежит на стороне «Нет» и слово «соглашаешься» путало.

Проверено скриптом: 102 карты, у каждой заменён ровно один текст, все тексты
оканчиваются вопросом, остальные поля побайтово совпадают со снапшотом.

## Цвета

Семантическая окраска «лайк/дизлайк по дельтам» (choiceTone, TONE_GLOW,
TONE_BUTTON_HOVER) **удалена** — она конфликтовала с красным/зелёным выбора.
Цвет теперь всегда означает одно: красный = отказ, зелёный = согласие.

Коды в `App.tsx`: `DISAGREE_STYLE` (red) / `AGREE_STYLE` (emerald).

## UX-изменения

- **Штампы НЕТ / ДА** на карточке (как в Tinder): непрозрачность растёт с
  длиной свайпа; показываются и при ховере кнопок на десктопе.
- **Улёт карточки** при выборе: ±60vw, поворот 26°, 180 мс, затем оверлей
  результата. На время улёта ввод заблокирован (exitDir).
- **Haptic**: `navigator.vibrate(12)` при коммите выбора.
- **Пороги свайпа** подняты с шумовых (2/8px) до осознанных: подсказка 10px,
  коммит 64px или флик > 0.35px/мс с проходом ≥ 24px; отмена по вертикали 60px.
- Мобильный звук свайпа (left/right) сохранён как был.

## Layout

- Игровой экран: `fixed inset-0 overflow-hidden` — страница не прокручивается
  при свайпе ни на телефоне, ни в узком окне.
- `touch-action: none` на игровой зоне (`touch-none`); скролл ленты сообщений
  и оверлеев оставлен (`touch-pan-y`).
- Вся игра центрируется колонкой `max-w-2xl`; карточка масштабируется:
  `max-w-sm → sm:max-w-md → lg:max-w-lg → xl:max-w-xl`, отступы и текст растут
  с экраном (`sm:text-base lg:text-lg`, эмодзи до 6xl).
- Компакт-режим для низких экранов: `@media (max-height: 700px/560px)` ужимает
  карту (min-height, паддинги, шрифты, кнопки).
- Safe-area: нижний отступ `env(safe-area-inset-bottom)`.
